# 省钱看板（dsh-money-board）

把 DeepSeek Harness 会话的 token 统计折成**钱**，直接显示在输入框上方。

## 它解决的问题

`save-token` 插件只报 token（进多少、出多少、压缩省掉多少），`dsh-cost-meter` 只报「花了多少」。两个数都在，但没人把「省下的 token」按当次的实际单价折成金额，于是「省了多少」永远只是一句无感的话。

这个插件补的就是这一环：**同一份 token 数据 × 官方价表 = 看得懂的人民币**，并且区分峰时/谷时，因为 DeepSeek 的峰时单价正好是谷时的两倍。

## 显示什么

一行徽标（输入框上方），与 `dsh-cost-meter` 那类状态条同一套排版——`·` 分隔的紧凑数字：

```
● 省钱看板 谷 ¥3.0554 · 省 ¥0.0276~1.3778 · 错峰 ¥3.0554
```

圆点颜色表示相位（绿=谷、琥珀=峰）。鼠标悬停出浮层明细，不占布局空间：

```
deepseek-flash   谷时（09:00 转峰时 ×2）
花费 ¥3.0554 = 未命中 ¥0.4949 16.2% · 缓存读 ¥1.5742 51.5% · 输出 ¥0.9863 32.3%
输入 240K · 缓存 17.1M · 输出 89.9K · 命中 99%
压缩省 ¥0.0276 ~ ¥1.3778（0.9% ~ 45.1%）
错峰：峰时 ¥6.1107，可省 ¥3.0554
260 次请求 · 压缩 11 次 · 重放 315 次 · 单价 0.02/1/4 每 1M
```

## 数据来源

1. **token**：本页同源读取 `/save-token/api/dashboard`（`save-token` 插件的私有只读路由），30 秒刷新一次。
2. **价格**：Host 半边直接 `import` 本机 `~/.dsh/profiles/<profile>/node_modules/dsh-cost-meter/lib/pricing.js`，用它的 `DEFAULT_PRICE_TABLE(_CNY)`、`DEFAULT_PEAK_WINDOWS`、`peakPhaseAt()`、`costOf()`。

因此**本插件不写死任何单价**：`dsh-cost-meter` 同步官方价格后，这里自动跟随。

## 为什么「省下的钱」是区间

`save-token` 只提供聚合的 `avoidedTokens`，无法还原每一次压缩分别按哪一档结算。于是给出上下界：

- **下限**：全部按缓存读价（¥0.02/1M）。历史重放走的就是这一档，所以真实值贴近下限。
- **上限**：全部按未命中价（¥1/1M）。仅当被压缩掉的内容是全新内容且只发一次时才成立。

## 用法与配置

装好即用。读不到的两种情况会在徽标上直说：

- `未检测到 save-token 插件` —— 先装 `dsh-plugin-save-token`；
- `缺少 dsh-cost-meter 价表` —— 先装 `dsh-cost-meter`。

配置项（`cordis.patch.yml` 的 `config`）：

| 键 | 默认 | 说明 |
|---|---|---|
| `currency` | `CNY` | `CNY` 用人民币价表，`USD` 用美元价表 |
| `model` | `auto` | `auto` 从 profile 的 `agent-default-model` 读取当前模型；也可写死模型 id |

## 已知限制

- 统计是 `save-token` 的**进程内累计**，重启 DSH 归零；本插件不做跨会话持久化。
- 依赖 `save-token` 的私有路由 `/save-token/api/dashboard`。该插件改字段名时，这里是静默变 0（已对每个字段做 `?? 0` 兜底，不会崩，但数字会失真）。
- 峰谷窗口取自 `dsh-cost-meter` 的常量（UTC 1–4、6–10 点 → 北京 09:00–12:00、14:00–18:00；周末与法定节假日整天空谷）。官方改时段后以该常量为准。
- 徽标每 30 秒刷新一次，不是实时逐请求计费。
